## 1. ЦЕЛИ И ГРАНИЦЫ СТЕЙДЖА 1

### Что входит строго в Стейдж 1:
1. **Полная очистка интерфейса:** убрать любые тестовые строки («Автотест»), серые крестики и посторонние корзины.
2. **Интерактивный календарь:**
   - Переключение месяцев стрелочками «<» и «>» с правильным расчётом дней недели, смещений и количества дней (включая високосные года);
   - Отображение цветных точек регулярных платежей на числах (VPN — цвет категории/настройки, интернет, ИИ);
   - Проекция платежей на короткие месяцы (февраль, апрель и т.д.): если платёж назначен на 31-е число, в месяце из 30 дней он проецируется на 30-е, а в феврале — на 28/29-е (`effectiveDay = Math.min(dayOfMonth, daysInMonth)`);
   - Если в один день совпадают два платежа — отображаются два цветных кружочка рядом на числе;
   - При клике на число/платёж — всплывает тактильный поповер прямо возле даты (на мобильном — нижняя шторка):
     * Если платёж один: название, сумма крупно (₽), прямая ссылка на магазин/оплату (`target="_blank"`) и кнопка-переключатель «Оплачено / Оплатить»;
     * Если платежей несколько: аккуратный список карточек с суммами, ссылками и кнопками оплаты;
     * Кнопка оплаты работает в контексте **просматриваемого месяца** (`viewedYearMonth`, например `2026-11`): нажатие переключает статус для просматриваемого месяца и **реактивно пересчитывает сумму на плашке «Расходы»** без перезагрузки;
     * Кнопка оплаты работает как toggle (при случайном нажатии можно нажать повторно и отменить статус);
     * Закрытие поповера: клик вне области, кнопка «✕», клавиша `Esc`, либо клик по затемнённому оверлею на телефоне.
3. **Три тактильные бумажные плашки сводки с реактивными показателями:**
   - *«Доходы» (мята)* — общая сумма поступлений за текущий месяц (₽) + список последних 3 поступлений;
   - *«Расходы» (персик)* — сумма оставшихся к оплате подписок в этом месяце (₽) + список ближайших платежей;
   - *«Клиенты» (небо)* — количество клиентов со статусом «В работе» + список ключевых клиентов;
   - Лишние плюсики с Главной убраны (добавление происходит в соответствующих разделах);
   - Клик по плашке плавно переводит в нужный раздел (`switchAppTab('income' | 'expenses' | 'clients')`).
4. **Адаптивность:**
   - Десктоп (1360px): левый сайдбар, просторный календарь, плашки сводки справа;
   - Мобильный экран (390px, iPhone): крупные сенсорные зоны $\ge 44\times 44\text{px}$, поповер платежей в виде нижней шторки с затемнением, плашки сводки друг под другом.

### Что НЕ входит в Стейдж 1 (границы):
- Детальные экраны Расходов, Доходов и Клиентов (это Стейджи 2, 3 и 4);
- Модальные окна добавления новых расходов/доходов/клиентов (Стейджи 2, 3 и 4).

## 2. СТРУКТУРЫ ДАННЫХ ДЛЯ ГЛАВНОГО ЭКРАНА

```javascript
// 1. Расход / Подписка (для календаря и плашки Расходов)
{
  id: "exp_1",
  title: "VPN (компьютер)",
  category: "vpn",
  dayOfMonth: 7, // 1-31
  currentRate: 1200,
  currency: "₽",
  color: "#D3E7F8",
  shopUrl: "https://example.com/vpn-pay",
  isArchived: false,
  paidMonths: ["2026-09", "2026-10"] // история оплат по месяцам
}

// 2. Доход (для плашки Доходов)
{
  id: "inc_1",
  clientId: "cli_1",
  clientName: "Анна Смирнова",
  project: "Дизайн сайта",
  amount: 15000,
  date: "2026-10-15"
}

// 3. Клиент (для плашки Клиентов)
{
  id: "cli_1",
  name: "Анна Смирнова",
  status: "work", // "discuss" | "work" | "waiting" | "done"
  color: "#C8E2D2",
  phone: "'+79161234567"
}
```

- **Логика статуса платежа в календаре:**
  Для выбранного месяца `viewedYearMonth` (например, `2026-11`):
  `isPaid = item.paidMonths && item.paidMonths.indexOf(viewedYearMonth) !== -1;`
  Статус отображается как «Оплачено» при `isPaid === true` и «Оплатить» при `isPaid === false`.
- **Проекция на дни месяца:**
  `effectiveDay = Math.min(item.dayOfMonth, daysInMonth(year, month));`
  Платёж на 31-е число всегда попадает на последний день короткого месяца (28, 29 или 30).
- **Сумма на плашке «Расходы»:**
  Сумма `currentRate` всех активных (`!isArchived`) подписок, для которых `!paidMonths.includes(currentYearMonth)`.

## 3. ПЛАН ТЕСТИРОВАНИЯ (TDD)
Файл тестов: `tests/stage1_calendar.test.js`

1. `test_calendar_month_switch`: корректный расчёт количества дней (28, 29, 30, 31) и дня недели начала месяца для любого месяца года при клике стрелочек «<» и «>».
2. `test_recurring_payments_projection_and_short_months`:
   - Платёж с `dayOfMonth: 15` проецируется на 15-е число;
   - Платёж с `dayOfMonth: 31` проецируется на 28/29 февраля и 30 ноября;
   - Архивные платежи (`isArchived: true`) игнорируются.
3. `test_twin_dots_on_same_day`: при совпадении 2 платежей на одну дату формируется массив из двух цветов.
4. `test_popover_multi_items`: клик по дате с несколькими платежами формирует список с названиями, суммами, ссылками `shopUrl` и кнопками действия.
5. `test_mark_paid_toggle_in_viewed_month`:
   - Нажатие «Оплачено» в календаре для месяца `2026-11` добавляет `2026-11` в `paidMonths` (а не текущий системный месяц);
   - Повторное нажатие удаляет `2026-11` из `paidMonths` (toggle);
   - Реактивно обновляет сумму на плашке «Расходы» без перезагрузки.
6. `test_summary_metrics_calc`:
   - Сумма доходов за месяц рассчитывается только по записям текущего месяца;
   - Сумма расходов к оплате суммирует только неоплаченные подписки текущего месяца;
   - Счётчик активных клиентов считает только статус `work`.
7. `test_summary_cards_navigation`: клик по плашкам вызывает `switchAppTab('income')`, `switchAppTab('expenses')`, `switchAppTab('clients')`.
8. `test_clean_dom_no_garbage`: в DOM Главного экрана отсутствуют строки «Автотест», серые крестики и корзины.
9. `test_popover_dismissal`: поповер корректно закрывается при клике вне области, нажатии `Esc`, клике по кнопке закрытия или клике на затемнение.
