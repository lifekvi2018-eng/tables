# ИНЖЕНЕРНЫЙ ПЛАН СТЕЙДЖА 3: ЭКРАН «ДОХОДЫ»
# Проект: «Мои таблицы ♡»
**Стейдж:** 3 из 5  
**Версия:** 2.0 (после Plan Review v3, Раунд 1)  
**Статус:** Готово к независимому Plan Review v3 (Раунд 2, уровни 1–3)  
**Цель:** Создать 100% живой экран «Доходы» с разноцветными карточками проектов клиентов, возможностью изменения полной стоимости, внесением платежей через светлый плюсик, раздельным хранением в Google Таблицах (`Проекты_Доходы` и `Платежи_Доходы`), реактивным обновлением плашки «Доходы» на Главном экране и строгим соблюдением Золотого стандарта модальных окон Ани.

## 1. ЦЕЛИ И АРХИТЕКТУРА СТЕЙДЖА 3

### 1.1. Что входит в Стейдж 3:
1. **Разноцветные карточки проектов клиентов:**
   - Карточки клиентов в фирменной тактильной палитре (мята `#C8E2D2`, персик `#FCD6CF`, лаванда `#DBCCE9`, небо `#D3E7F8`);
   - В шапке карточки: Имя клиента, Название проекта/услуги и **Полная стоимость проекта** (например, `80 000 ₽`);
   - Кнопка изменения суммы проекта (карандашик) прямо на плашке: по клику открывается мини-модалка по Золотому стандарту («Изменить стоимость проекта», инпут суммы, кнопки «Отмена» `#FDF1CC` и «Сохранить» `#C8E2D2`, `border: none`);
   - Никаких перегруженных расчетов остатков и сложных графиков — простой и понятный фокус на деньгах.
2. **Внесение оплат через светлый плюсик (`+`):**
   - Внутри карточки проекта отображается лента внесённых оплат в виде аккуратных светлых бумажечек;
   - Рядом с заголовком платежей — круглый светлый плюсик `+` («+ Внести платёж»);
   - Нажатие `+` открывает модальное окно добавления оплаты строго по **Золотому стандарту Ани**;
   - В модалке оплаты:
     * *Сумма платежа* (число в ₽, строго больше нуля);
     * *Дата оплаты* (ГГГГ-ММ-ДД, по умолчанию сегодняшняя дата);
     * *Заметка / За что* (текст, например: «Аванс 50%», «Второй платёж», «Оклад за октябрь»);
   - После сохранения появляется светлая плашечка с датой и суммой;
   - Клик по плашечке платежа открывает модалку «Редактировать платёж» с возможностью изменить сумму/заметку либо нажать кнопку «Удалить платёж» (пастельный коралл `#FCD6CF`, текст `#58241B`, `border: none`);
   - Платежей может быть 1, 2, 3 или сколько угодно (для клиентов на абонентской плате / окладе);
   - В оплате нет промежуточных статусов: «Оплатил — я записала, всё».
3. **Модальное окно «+ Новый проект» (Золотой стандарт):**
   - Поля ввода:
     1. *Клиент* (выбор из выпадающего списка существующих клиентов или свободный ввод нового имени);
     2. *Проект* (название услуги / проекта);
     3. *Полная стоимость* (в ₽);
     4. *Выбор цвета карточки* из палитры кружочков (мята, персик, лаванда, небо, сливки, коралл);
   - Автономия от Стейджа 4: список клиентов динамически строится из уникальных имён клиентов, уже сохранённых на листе `Проекты_Доходы` (плюс ввод нового). `ID_Клиента` является опциональным и не блокирует автономную работу Стейджа 3;
   - Дизайн: строго по стандарту Ани (`border: none`, внешний фон `#FAF2E7`, плашка `#FCE8D5`, отмена `#FDF1CC`, сохранить `#C8E2D2`).
4. **Архивация проекта:**
   - В шапке карточки проекта (рядом с суммой) размещена аккуратная иконка архивации;
   - При клике открывается диалог подтверждения по Золотому стандарту («Отправить проект в архив? Платежи сохранятся в истории. [Отмена] [В архив]»);
   - Проект помечается `В_Архиве: TRUE` и скрывается из активного экрана Доходов, а все строки платежей остаются в Google Таблицах для годовой финансовой отчётности.
5. **Реактивная связь с Главным экраном:**
   - Плашка «Доходы» Главного экрана отображает сумму фактических оплат, совершённых **в текущем календарном месяце** (`viewedYearMonth`);
   - Платежи за пределами текущего месяца (прошлые или будущие) НЕ увеличивают показатель текущего месяца на Главной;
   - Реактивное обновление сводки (`updateSummaryCards()`) срабатывает при любом действии: 1) добавление платежа текущего месяца, 2) изменение суммы платежа текущего месяца, 3) удаление платежа текущего месяца.
6. **Адаптивность для телефона и компьютера:**
   - Сенсорные зоны $\ge 44\times 44\text{px}$ для кнопок плюсика и действий;
   - Удобный ввод сумм на тачскрине телефона;
   - Отсутствие строки поиска (чистый просторный экран).

### 1.2. Что НЕ входит в Стейдж 3 (границы изоляции):
- Экран «Клиенты» с CRM-анкетами, паролями и 4 статусами (Стейдж 4);
- Экран «Расходы» и подписки (Стейдж 2);
- Алгоритм сетки календаря Главного экрана (Стейдж 1);
- Официальный Google Sign-In Gate (Стейдж 5).

## 2. СТРУКТУРА ХРАНЕНИЯ В GOOGLE ТАБЛИЦАХ
Схема полностью синхронизирована с каноническими заголовками `ТЗ_Мои_Таблицы.md` v2.0 для идеальной работы формул `=SUMIFS`:

### Лист 1: `Проекты_Доходы`
| Колонка | Тип | Описание |
|---|---|---|
| `ID` | string | Уникальный ID проекта (`inc_proj_...`) |
| `Клиент` | string | Отображаемое имя клиента |
| `Проект` | string | Название задачи/проекта |
| `Полная_Стоимость` | number | Текущая договорная стоимость проекта в ₽ |
| `Цвет` | string (hex) | Пастельный цвет карточки (`#C8E2D2`, `#FCD6CF`, etc.) |
| `ID_Клиента` | string | Опциональный ID клиента (для связки со Стейджем 4) |
| `В_Архиве` | boolean | `TRUE` если проект архивирован, `FALSE` для активных |
| `Дата_Создания` | string | Дата добавления проекта (ГГГГ-ММ-ДД) |

### Лист 2: `Платежи_Доходы`
| Колонка | Тип | Описание |
|---|---|---|
| `ID` | string | Уникальный ID транзакции (`inc_pay_...`) |
| `ID_Проекта` | string | Внешний ключ связки с `Проекты_Доходы` |
| `Дата` | string | Дата фактического получения денег (ГГГГ-ММ-ДД) |
| `Сумма` | number | Фактически внесённая сумма в ₽ |
| `Заметка` | string | Комментарий («Аванс», «Окончательный расчёт», «Оклад») |

## 3. ЗОЛОТОЙ СТАНДАРТ ИНТЕРФЕЙСА (УТВЕРЖДЁН АНЕЙ)
Все модальные окна Стейджа 3 («+ Новый проект», «+ Внести платёж», «Редактировать платёж», «Изменить стоимость», «Подтверждение архивации») строго реализуют стандарты:
1. `border: none` — полное отсутствие рамок, подводок и ободков. Объём задаётся исключительно через мягкие 3D-тени бумаги (`box-shadow`).
2. Полный запрет на чисто белый цвет (`#FFFFFF`).
3. Внешнее окно модалки: фон бумаги `#FAF2E7`, радиус 24px, мягкая глубокая тень, `border: none`.
4. Внутренние плашки полей: тёплый персик `#FCE8D5` (или цвет проекта из палитры), радиус 18px, `border: none`.
5. Кнопка «Отмена»: тёплые нежные сливки `#FDF1CC` (не белая!), текст `#5B481D`, `border: none`.
6. Кнопка «Сохранить»: нежная мята `#C8E2D2`, текст `#1E3F30`, `border: none`.
7. Кнопка «Удалить платёж» / «В архив»: мягкий коралл `#FCD6CF`, текст `#58241B`, `border: none`.

## 4. ПЛАН ТЕСТИРОВАНИЯ (TDD)
Файл тестов: `tests/stage3_income.test.js`

1. `test_create_project_validation`:
   - Проверка создания проекта с валидными полями (Клиент, Проект, Стоимость > 0, Цвет);
   - Отказ при пустом имени клиента или нулевой/отрицательной стоимости;
   - Запись корректной строки на лист `Проекты_Доходы` с каноническими полями `Клиент`, `Проект`, `Полная_Стоимость`.
2. `test_update_project_total_cost`:
   - Возможность изменить полную стоимость проекта (например, с 80 000 до 100 000 ₽);
   - Обновление поля `Полная_Стоимость` без повреждения истории платежей.
3. `test_payment_validation`:
   - Проверка запрета сохранения платежа с суммой <= 0, пустой суммой или NaN;
   - Автоматическая подстановка сегодняшней даты в формате YYYY-MM-DD при пустом поле даты;
   - Корректная обрезка пробелов в поле `Заметка`.
4. `test_add_payment_appends_to_payments_sheet`:
   - Нажатие `+` и сохранение платежа (сумма 30 000 ₽, дата `2026-10-15`, заметка «Аванс»);
   - Запись отдельной строки в `Платежи_Доходы` с каноническими ключами `ID`, `ID_Проекта`, `Дата`, `Сумма`, `Заметка`.
5. `test_multiple_payments_summation`:
   - Проект с 3 платежами (20 000 + 30 000 + 10 000 ₽) возвращает корректную сумму внесённых оплат (60 000 ₽);
   - Проверка отсутствия промежуточных статусов (все платежи честно зафиксированы).
6. `test_edit_and_delete_payment`:
   - Клик по плашке платежа позволяет изменить сумму или удалить транзакцию;
   - При удалении строка удаляется из `Платежи_Доходы`, проект остаётся нетронутым;
   - Реактивная корректировка сводки.
7. `test_archive_income_project`:
   - Выставление `В_Архиве: TRUE` скрывает проект из активного экрана Доходов;
   - Все строки в `Платежи_Доходы` остаются в базе для истории и годовых отчётов.
8. `test_reactive_summary_cards_sync`:
   - Платежи за пределами текущего месяца (например, `2026-09-25`) НЕ влияют на плашку текущего месяца (`2026-10`);
   - Добавление, редактирование суммы или удаление платежа за текущий месяц реактивно обновляет сумму на плашке «Доходы» Главного экрана (`updateSummaryCards()`).
9. `test_clean_dom_no_white_no_borders`:
   - Проверка отсутствия чисто белого цвета `#FFFFFF` и `border` в стилях модальных окон Доходов.
