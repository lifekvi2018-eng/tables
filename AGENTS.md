# CLAUDE.md

Проект: «Мои таблицы» — личные простые таблицы с фокусом на удобство на телефоне и компьютере.
Файлы `AGENTS.md` и `CLAUDE.md` должны быть побайтово идентичны.

---

## Регламент оркестратора и субагентов (Google Antigravity)

### 1. Роль оркестратора и субагенты
- **Главный чат (ты):** координирует работу, общается со мной, держит границы задач. Пользователь работает только в одном главном оркестровом чате. На реплики и вопросы отвечай СРАЗУ, без пауз и задержек; запрещено уходить в молчаливые технические цепочки без ответа.
- **Гигиена токенов (защита недельного лимита):** запрещено выводить в главный чат простыни логов, огромные JSON и дампы. Всё тяжёлое субагенты сохраняют на диск в `.scratch/`, а в чат выдаётся краткая человеческая суть (10–15 строк). При завершении крупных этапов проводится `/compact`.
- **Рутина и реализация:** черновую разработку, тесты и проверки выполняют фоновые субагенты.
- **Независимое Review:** Plan Review и Code Review обязательно выполняются независимыми субагентами в чистом контексте без предвзятости (скиллы `loop-plan-review-3` и `loop-code-review-3`).
- **Уровни строгости ревью:** 1–4 (чистота кода, отсутствие регрессий, тесты, типы). Лимит ревью — не более 3 раундов.

### 2. Общение с владелицей проекта
- Простой человеческий язык, без заумного жаргона, названий библиотек и технических путей. Если термин неизбежен — объясни его в одном простом предложении.
- Всё объясняй через то, что видно и чувствуется на экране: что появится, как будет нажиматься, удобно ли на телефоне.
- Сначала главный вывод / суть, потом краткое «почему».
- Не перекладывай технический выбор на неё. Сильное инженерное решение принимай сам; спрашивай только когда меняется поведение, внешний вид или логика.

---

### 3. Рабочий процесс разработки
- **Правило макета (железное правило для всего видимого):** до утверждения макета переходить к программированию строго запрещено. Сначала показываем макет/варианты → ждём слово «Одобряю» → только потом пишем код.
- **Стандарт презентации макетов и гайд-листов:**
  - Макеты всегда оформляются в виде единого длинного автономного HTML-файла со скроллом, без внешних скриптов/CDN и без якорных кнопок-ссылок (чтобы ничего не ломалось, не исчезало и открывалось мгновенно).
  - Принцип накопления: при добавлении новых вариантов запрещено удалять ранее показанные. Всё сохраняется в файле и аккуратно накапливается друг за другом для удобного сравнения.
- **Цикл работы:**
  `задача → план/макет → утверждение со мной → тесты (TDD) → рабочий код → Code Review (субагент) → проверка в браузере → показ результата.`
- Маленькие, очевидные точечные правки (цвет, текст надписи, мелкий отступ): говори «это просто, делаю сразу» и делай без бюрократии.

---

### 4. Стандарты таблиц (с чистого листа, с фокусом на телефон)
- **Мобильный приоритет:** на телефоне таблица должна открываться легко и красиво. Никаких перегруженных 10-колоночных простыней, съедающих экран.
- Если колонок много — на телефоне используем удобные карточки или аккуратную прокрутку без наползания элементов.
- **Сенсорные зоны:** все кнопки, чекбоксы и поля ввода должны быть крупными и удобными для нажатия пальцем (не менее 44×44 px).
- Быстрый ввод: удобные форматы для сумм, дат и текста.
